# 07 调研：阅读页的文字排版与整体样式

> 2026-11-16。状态：**用户已确认，默认排版已接入桌面和手机阅读组件，尚未发布**。调研依据为工作区源码、现行视觉规范、项目旧截图及公开资料；优化前证据与原型检查保留如下，正式组件的实施与验证见 §8。未完成 Tauri 原生窗口 / iPhone 真机验证。
>
> [交互对比稿](../prototypes/reader-typography.html)：同内容切换当前样式重建 / 建议版，支持桌面 / 手机、浅色 / 深色 / 米色、译文、释义、标注、字号，以及 Source Serif 4 / Literata / Charter 三款字体。它用于评审排版，不连接应用数据；外壳简化，不代表功能已实现。

## 1. 结论

已采用围绕**正文节奏、原文与译文的分组、学习标注的重量**的优化方案。保留现行「安静的 AI 工作台」与白色纸面，默认阅读字体选择 Source Serif 4；Literata 与 Charter 留在对比稿作为参考（§7）。

**用户确认的约束（2026-11-16）**：译文不放大，保持现有桌面 14.5px、手机 14px；本轮只优化其分组与间距，正文调大时也不联动放大译文。

现有桌面 19px / 1.75 的正文基础并不差，720px 外框包含两侧各 32px，实际文字列最多 **656px**，不能简单诊断为正文过宽。建议试读 20px / 1.7、640px 文字列；这是待验证的审美选择，而非可读性标准的唯一答案。

手机端优先级更高：每个英文 token 额外左右各 1px 的 padding 会累积成松散的词间距；正文、列表、引用的字号也不统一。应先修复这些明确的不一致，再考虑字体切换等可选项；译文维持独立的小字号层级。

## 2. 优化前实现的证据

| 位置 | 当前行为 | 对阅读的影响 / 判断 |
|---|---|---|
| `apps/desktop/src/styles.css` `.rd` | 19px / 1.75，max-width 720px，左右 32px | 实际文字列 656px，基础合理；建议小幅试调而非大幅加行高 |
| `apps/desktop/src/pages/Reader.tsx` | 标题、正文、结束区分三个容器；前后两处内联重复 720px / 32px | 容易在后续修改行宽时错位；实施时统一一个阅读列参数即可，无须新布局框架 |
| 同上 / `.rd .meta` | 类型、时间、难度、来源、生词数及新用户提示在标题之前 | 信息密集；建议标题前只保留简短来源 / 类型 / 时间，生词数移至学习工具附近，新手提示按首次显示 |
| `apps/desktop/src/reader/Section.tsx` | 段落和译文是相邻节点，译文在段距后通过负 margin 拉回 | 视觉上不易形成稳定的「一段原文 + 一段译文」；字体调整后关系更难维护 |
| `styles.css` `.rd .tr` | 固定 14.5px / 1.75，左侧 2px 浅蓝线，`margin-top: -.45em` | 按用户意见保留 14.5px，以组内间距区分，取消每段竖线 |
| `apps/desktop/src/mobile/mobile.css` `.w` | **所有 token** 左右各 1px padding | 每个词都扩宽 2px，改变自然词间距和换行；建议取消布局 padding，标注不改变字宽 |
| 同上 `.rd p / li / blockquote` | 段落 19px / 1.75；列表 18px / 1.7；引用没有单独指定阅读字体 | 列表节奏不同；引用可能落回界面字体 / 基础字号，应随阅读正文继承 |
| 同上 `.rd .tr` | 14px / 1.7，负 margin -10px，末尾又重复一条 margin 规则 | 标题、引用、列表后的译文也套固定上提量，不够稳；用语义组内间距更直接 |
| 桌面 `.rd.gloss` / 手机 `.gl .rd p` | 桌面给段落、列表扩行高；手机只对段落扩行高 | 手机上列表里的行间释义存在碰撞风险，需要同一验收样本检查 |
| 桌面 `.w.s0…s4` | 高亮从字面 34% 到 90%；手机是 55% 到 92% | 两端重量不一致；建议统一约 57%–91% 的下部荧光笔，保留现有蓝 / 黄熟练度语义 |
| `03-visual-language.md` / `docs/prototypes/reader.html` | 规范和旧原型有字体 / 字号 / 行高 / 行宽设置 | 正式阅读页尚无完整入口；应明确「设计已有、实现未齐」，不当作新增需求全部一次补齐 |
| 字体资源与 CSS | 阅读栈为 Charter / Charis SIL / Georgia；检查到的 `src/assets/fonts` 只有首页用的 Yozai | 写了 fallback 名不等于随包提供了字体；正式应用本轮不新增字体资源。后续字体对比仅在原型加入本地字体文件，见 §7 |

移动端单词 padding 的收益最确定；标题尺寸、译文竖线与标注覆盖高度属于设计建议，需以对比稿和实际试读决定。

## 4. 推荐排版参数（试读起点）

| 元素 | 桌面 | 手机 | 原因 |
|---|---|---|---|
| 阅读字体 | **Source Serif 4**，Latin 子集随包提供 | 同左 | 已确认并接入默认阅读页；其他页面保留 Charter |
| 正文 | **20px / 1.7** | **19px / 1.72** | 桌面稍增加字面，手机保持字号，避免行高一味变大 |
| 文字列 | 最大 **640px**；外框 704px 含 64px padding | 两侧 **24px**，小屏需复核 | 前后容器共用宽度与边距；右面板打开时以可用空间自然收窄 |
| 标题 | 36px / 1.18 | 30px / 1.18 | 建立标题层次；长标题允许自然多行，不能截断 |
| 顶部留白 | 元信息距正文容器顶 46px | 导航下约 24px | 让文章开头更从容；对比稿数值，最终随真机视野校准 |
| 标题到正文 | 30px | 28px | 从分散容器的默认 padding 改为明确间距 |
| 普通段间距 | 1.25em | 1.25em | 用段间留白建立节奏，不缩进首行 |
| 原文到译文 | 8px | 8px | 小于组间距，使两者归为一组；取消负边距 |

| 小标题 | 正文的 1.2 倍，上 1.9em / 下 .6em | 1.18 倍，上 1.65em / 下 .6em | 上松下紧，靠近它统领的内容 |
| 列表、引用 | 继承正文基础字号，局部控制间距 | 同左 | 避免视觉上突然缩成另一套文字 |

不建议本轮加入纹理、纸张投影、渐变、首字下沉、两端对齐、按文体自动切字体或更多装饰颜色。继续使用现行主题色；「米色」只是外观选项，不据此宣称医学护眼效果。

## 5. 实施范围与后续

1. **已实现：默认排版。** 手机取消 token padding；统一阅读列的宽度 / 边距；调整标题、段距、原译文间距，保持译文字号；列表 / 引用继承正文；统一高亮高度。沿用现有分词、选词、翻译任务和熟练度规则；字体加载后恢复原有比例阅读位置。
2. **已实现：原译文成组。** 普通段、标题、引用各自有一层 `.rdblock` 分组；列表译文继续留在 `<li>` 内，保留 `data-sid` / `data-para` 和单词事件，不引入新渲染库。
3. **第二批：外观入口。** 默认版式确认后，再用一个 `Aa` 面板收拢字号、行距、行宽、纸面；先保留现有字体，字体切换待验证跨平台资源后补齐。阅读页两个端各自用现有 UI 组件，不新增一套全局主题系统。
4. **已同步规范。** `03-visual-language.md`、`00-concept-design.md` 的阅读器段落及实现状态已更新，`CHANGELOG.md` 记录本地改动；原型保留字体与版式对照。

优先完成第一批并试读，再决定第二批；不要一次扩成阅读器重构。

## 6. 验收与本轮边界

实施时至少检查：

- 技术文章（行内代码、代码块）、小说（长段落、长章名）、列表 / 引用 / 超长链接；同一篇切换译文前后，组关系清楚。
- 桌面 960 / 1280 / 1440 宽度，侧栏收起 / 展开，总结面板打开 / 关闭；正文、标题和结束区对齐。
- 手机 320 / 375 / 393 / 430 宽度，浅色 / 深色 / 米色，常规字号与放大；无横向溢出、文字裁切和工具条遮住文末。
- 行间释义在段落、列表、引用及相邻生词密集时没有重叠；降低标注高度后仍能分辨熟练度，词卡点击命中正常。
- 字号调整 / 译文插入后，阅读位置、选区问 Tibi、搜索定位和朗读句高亮仍正确。
- 用户覆盖 WCAG 1.4.12 的四种间距后无内容 / 操作丢失；这与默认美观评审分别验证。

调研阶段仅有文档与静态交互稿，不能把原型截图当作真实阅读器验收。对比稿保留独立容器以便原位切换，不演示真实工具条、词卡或右面板行为；后续正式组件实施见 §8。

**本轮原型检查结果**：初稿使用本机 Chromium 检查 320 / 393 / 960 / 1440px 视口 × 3 种内容 × 默认 / 放大字号，共 24 组，打开译文及行间释义后未出现页面或阅读容器横向溢出，也没有脚本异常；列表与正文计算字号一致。额外检查了三种纸面主题与当前 / 建议版切换；通过浏览器实际渲染字体信息确认英文样本使用 `Charter-Roman`，建议版桌面文字列为 640px。已查看初稿桌面和手机预览截图。用户反馈后，译文改回桌面 14.5px / 手机 14px，组内间距固定为 8px；初稿截图不代表此次修订。以上不证明相邻释义没有重叠、WCAG 合规或真实应用功能通过验收。

## 7. 字体候选补充（2026-11-16）

用同一内容、字号、行宽和间距比较三款字体后，用户确认按 **Source Serif 4 作为默认正文**的方案实施。Literata 为偏书籍风格的备选，Charter 保留对照。这是设计选择，不代表某款字体对所有人的阅读效率更高。

| 字体 | 外观与适用性判断 | 已核实的信息 / 注意点 |
|---|---|---|
| **Source Serif 4（首选候选）** | 相比现有 Charter，笔形更柔和，标题与正文都较克制；适合技术文章、新闻、小说共用的一套阅读字体 | Adobe 的开源正文字体，具有 `wght` 字重和 `opsz` 光学尺寸轴；可按字号调整笔形与间距细节。原型开启 `font-optical-sizing: auto` |
| **Literata（备选）** | 字面更饱满、书卷感更强；适合长篇小说。相同 CSS 字号下密度与换行不同，需比较深色下的重量 | TypeTogether 最初为 Google Play Books 设计；后续版本支持字重、光学尺寸轴。原型使用可变字体，并提供真实斜体 |
| **Charter（现行对照）** | 紧凑、结实，阅读基础仍然良好；如果更偏好清爽精致的观感，可以先看 Source Serif 4 | macOS 本机渲染已确认；其他平台的 fallback 不保证字形一致 |

中文译文保持系统字体与现有 14.5px / 14px 字号；不随英文字体切换，也不放大。代码仍用等宽字体。英文标题随正文切换，用于比较一套字体覆盖整篇文章的效果，暂不增加单独的标题字体选项。

两款候选字体均采用 SIL OFL 1.1；原型保存来源许可原文，并使用 Google Fonts 提供的 Latin 子集 WOFF2（正体与斜体各一份，共约 417 KiB）。原型资源在 `docs/prototypes/fonts/reading/`，不加载第三方字体服务。正式应用仅接入 Source Serif 4（两文件约 246 KiB），中文保留系统字体，Latin 字集外回退到现有 Charter / Charis SIL / Georgia；Literata 不随应用打包。

核对来源：[Adobe 官方字体样张](https://adobe-fonts.github.io/source-serif/)、[Source Serif 源仓库](https://github.com/adobe-fonts/source-serif)、[TypeTogether Literata](https://www.type-together.com/literata-font)、[Literata 源仓库](https://github.com/googlefonts/literata)。文件来源、大小和许可见[原型字体记录](../prototypes/fonts/reading/README.md)。

**字体原型检查**：本机 Chromium 已确认三款字体的正文、粗体标题和斜体引用均实际使用对应字体；两款候选从本地 WOFF2 加载，未落回 Georgia。检查三款字体 × 桌面 1440 / 手机 393 / 手机 320px × 默认 / 放大字号，共 18 组，开启译文和释义后未出现阅读容器横向溢出，无脚本异常，译文始终保持桌面 14.5px / 手机 14px。已查看同内容、同字号的三款字体并排截图；iOS 真机字重与光学尺寸效果仍待正式实施后验证。

## 8. 正式组件实施与验证（2026-11-16）

用户确认后，已接入桌面与手机阅读页，尚未提交发行或发布新版本：

- `src/reader/fonts.css` 为两端引入本地 Source Serif 4 正体 / 斜体，字体位于 `src/assets/fonts/`，许可经 `public/licenses/SourceSerif4-OFL.txt` 随生产包分发。仅阅读页改用 `--f-article`，其他页面保留原 `--f-read`。
