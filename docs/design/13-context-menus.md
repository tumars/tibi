# 13 右键菜单：围绕阅读对象操作

> 2026-11-17，**P0 阅读页与 P1 对象菜单已接入本地桌面应用，尚未发版**。§2 保留实施前的调研证据，§8 / §9 记录实施与验证。现行阅读器见 [00 §3.2](00-concept-design.md#32-阅读器reader)，mac 菜单沿用 E5。[独立交互稿](../prototypes/context-menus.html)仍是演示；正式代码已接通 Core。

## 1. 要解决的问题

阅读时，用户已经指着一个词或选好一段话，却还要先开词卡、移动到工具栏或自己组织问题。右键应让用户直接操作眼前的内容，保留阅读位置与上下文。

**建议先做桌面阅读页：按单词、选区、句子、正文空白提供不同菜单。** 左键查词与现有工具栏保留；菜单只选命令，释义、回答与播放状态仍在词卡、现有右栏和朗读条呈现。

第一批不扩成笔记 / 摘录系统，不增加批量“标为已知”，不把删除文章、重新分析、导出和模型设置搬进阅读页。

## 3. 阅读页菜单

“／”为同组，“｜”为分隔线，“›”为唯一一层子菜单。文案随应用语言变化。

| 右键对象 | 菜单顺序 | 结果落点 |
|---|---|---|
| 英文单词 | **查词**／朗读单词／问 Tibi：这里的意思｜标为生词／标为已知｜复制单词／所在句子 › | 原有词卡、Tibi 右栏；标词更新原文并给撤销 |
| 所在句子 › / 句子菜单 | **问 Tibi：解释这句**／朗读这句／从这里朗读｜复制这句 | Tibi 右栏与现有朗读条 |
| 合格的英文短语选区 | **问 Tibi：解释选中内容**／朗读选中内容｜加入短语｜复制选中内容 | 收录为一个短语，不逐个收录所选单词 |
| 普通原文选区（含跨句 / 段） | **问 Tibi：解释选中内容**／朗读选中内容｜复制选中内容 | 使用所选文字，不悄悄替换为整句或整章 |
| 正文空白 / 段落外边距 | **在本章查找…**／显示译文（或隐藏译文）／标注模式 ›｜回到开头｜打开原文 | 查找、译文及标注沿用现有状态 |
| 来源链接 | **打开原文**／复制原文链接 | 系统浏览器，沿用安全 URL 打开规则 |
| 代码块 | **复制代码**；有代码选区时为“复制选中代码” | 保留换行与缩进，不出现学习标记 |
| 仅译文内的选区 | **复制选中内容** | 第一批不将中文译文作英文学习材料 |

细则：

- 单词菜单 **7 项、最多 3 组**。完整六档熟练度与忽略留在词卡，只将最常用的“生词 / 已知”放在快捷菜单。
- “标为已知”是 **97**，不等于复习达到的“掌握 5”。当前为 97 时显示勾选；为 5 时该位置显示勾选的“已掌握”，不再改写为 97。重复标同一状态不写入；其他状态可显式改为生词 0。
- **只有执行“查词”才沿用 R5 点词规则。** 发音、复制、打开菜单与子菜单均不改变学习状态。
- “加入短语”仅在选区对齐完整 token、位于同一英文原句、2–8 个词、总长 3–80 字符，且未夹入代码 / 译文时出现；排除带句末标点的完整句选区。8 词是本次建议上限，不是语言学判定。
- 用不带 `sentence_id` 的只读 `terms.lookup` 检查短语；已有条目改为“查看短语”，不重复 `addPhrase`。新短语沿用当前接口的见过 1。检查时该位置显示不可执行的“正在检查短语…”，失败可重试，不阻塞复制 / 解释；这是短暂加载状态的例外。
- 原文选区超过 600 字符时保留完整复制，隐藏解释与朗读；在浮条“更多”旁提示“解释和朗读请选 600 字符以内”，不截断后发送。单字母单词也能查词，不套用现有浮条的两字符门槛。
- 空白菜单没有“复制”“读完了”或“全章标为已知”。无网页来源时隐藏“打开原文”，已在开头时隐藏“回到开头”。
- 图片等非文本对象第一批保留平台行为；混合原文 / 译文选区只提供复制，内容与可见选区一致。

## 4. 交互规则

### 4.1 目标解析

顺序：**可编辑区域放行 → 指针位于有效选区内 → 来源链接 / 代码 → token → 原句 → 正文空白**。图片等非文本对象在空白分支前排除。

- 选区须完全位于本次正文范围内；用 `Range.getClientRects()` 判断指针是否点在所选文字上，不用跨行大矩形吞掉空白。选区外右键移除旧的无关选区，按实际落点操作。
- 单词使用 token 的原文、原形、偏移和所属句子，不用系统自动选词猜边界。只选中一个完整 token 时使用单词菜单。
- 次键按下（含 mac Control-click）时保存目标所需信息；打开前冻结文档 / 章节 / 句子 / 词 / 选区。焦点进入菜单后不能重新读取 Selection 猜目标。
- 切章、离开页面后不执行旧菜单回调；异步短语查询晚到时不能污染新目标。

### 4.2 与现有交互协调

- 右键不触发左键词卡，也不触发朗读模式“点击句子即跳读”。打开菜单时隐藏选区浮条、关闭旧词卡；取消不清当前有效选区，不标词、不播放。
- 点菜单外、滚动、切章或窗口失焦关闭；Esc 先关最上层菜单，焦点回原文目标或触发按钮，不跳到页面顶部。
- 解释复用 `ask(text, { sentence_id, selection })`；跨句选区不伪造覆盖全部内容的 `sentence_id`，仍带文档与章节上下文。回答进入已有文章对话。
- AI 未连接时保留解释入口；执行后在 Tibi 面板提示连接并保留材料，连接后由用户发送，不自动补发。不开菜单即预生成，也不因弹菜单下载语音模型。
- “朗读单词 / 这句 / 选区”读完即停；“从这里朗读”从目标句开始连续读。复用现有 TTS，启动一项停掉上一项，避免叠音；已有倍速等设置保留。
- 本地查词、复制、状态标记、系统朗读不依赖 AI。词典缺失、剪贴板拒绝、TTS 不可用、写入失败均给真实错误，不虚报成功；AI 失败在右栏重试。

### 4.3 可发现性与键盘

1. 选区浮条保留“问 Tibi”，追加可聚焦的“更多操作”，与右键使用同一份命令。
2. 句子入口在悬停 / 键盘定位到该句时显示小型 `…`，指向明确的句子；不常驻每句标点旁。键盘先定位正文区，再在句子间移动，不给每个单词增加 Tab 停靠点；此导航需在实施阶段验证辅助技术。
3. 单词操作仍可从左键词卡访问，复制保留系统编辑命令；空白操作保留工具栏、查找和来源入口。
4. Web / Windows / Linux 支持菜单键、Shift+F10，方向键、Home / End、Enter、Esc、Tab 退出；mac 支持次键与 Control-click。快捷键只在主菜单等适当位置显示，不在右键中重复。

手机长按与系统选区冲突较大，第一批不搬桌面手势；后续复用操作语义，另设计系统选区 / 底部抽屉。**交互稿的窄屏只方便看稿，不代表手机实施方案。**

## 5. 外观与平台

- **macOS 桌面继续用原生菜单**：扩展 `lib/macNative.ts` 所需的分隔线、勾选、一级子菜单与定位；字体、尺寸、圆角和菜单主题交给系统。
- **Web / Windows / Linux**：复用项目已有 `@radix-ui/react-dropdown-menu` 的受控菜单，在指针坐标放置一个不可交互的 1px 锚点，继续由 Radix 处理子菜单、勾选、键盘、焦点与碰撞。新增薄的 `ContextMenu` 展示组件；原有按钮下拉 `Menu` 保持原用途，无新增依赖。
- HTML 稿只近似密度：13.5px 系统字体、约 220px 宽、约 28px 行高、6px 内边距、细边线和轻投影。不塞释义、回答、大标题或快捷键列。
- 靠近视口边缘时菜单及子菜单翻转，Web 留至少 8px 边距。菜单贴指针，不固定挂在左栏。
- 输入框、设置和聊天输入区保留系统剪切 / 拷贝 / 粘贴 / 拼写。接管阅读正文右键后，系统 WebView 的“查询 / 翻译”不会自动合并；第一批以 Tibi 查词为主，mac 服务仍可从应用菜单访问。如需原位保留系统查询，须另验证原生桥接，不画作已支持。

## 6. 实施范围

### P0：桌面阅读页（已本地实施）

| 改动 | 直接做法 |
|---|---|
| 目标与协调 | `SectionView` 暴露 token 原始偏移与句子入口；`ReaderMenu` 将 DOM 落点映射回本章原 token / 原句并冻结本次目标，`Reader` 复用词卡、ask、翻译、查找与标注 |
| 菜单展示 | mac 交给 Tauri，其他环境复用 Radix 菜单；只支持本次需要的 item / separator / checked / submenu，不建全局命令总线 |
| 写入与撤销 | 单词用 `terms.mark`；短语只读查重，新建用 `terms.addPhrase`。RPC 返回已有 `undo`，同步接口源文档、types 与生成文件；避免旧短语撤销误删已有词条 |
| 朗读 | 给现有朗读条传目标句与启动请求，复用 `goto`；已打开时也可跳转，不靠重挂载重置用户设置 |
| 入口与文案 | 选区“更多”、句子入口、键盘行为；新文案补英文，不顺手扩展整套单键系统 |

**macOS 原生菜单生命周期**：Tauri 2.12.5 的 `Menu.popup()` 在 AppKit 跟踪菜单期间持有 WebView 资源表的锁。AppKit 仍会处理 WebView 消息，点菜单命令后执行资源清理时可能与弹出流程死锁。改由壳的 `popup_context_menu` 取得菜单引用并释放锁后再弹出。菜单退出后动作事件仍可能在投递，前端在卸载或下一次弹出时释放资源。

### P1：应用对象菜单（已本地实施）

| 对象 | 已接入操作 |
|---|---|
| 书架卡片 / 行 | 打开 / 继续阅读、编辑标签、有来源时打开 / 复制链接；行内 `…` 提供同样入口，不借此新增删除流程 |
| 生词本行 | 打开详情、发音、复制、改熟练度；移出生词本独立分组并可撤销。复习作答区不增加绕过评分的状态菜单 |
| 订阅文章 | 阅读、加入书架、打开原文；区分隐藏文章与删除订阅源 |
| 最近对话 | 维持已有重命名 / 删除，补位置与键盘一致性 |
| 聊天回答 | 保留选区复制与整条复制，不将聊天文字当阅读 token |

P1 不新增批量操作、文章删除与订阅源删除入口；详细行为与验证见 §9。

## 7. 验收与本次边界

正式实施至少检查：

1. 单词 / 单字母 / 词形、0 / 1 / 5 / 97 / 98；仅开菜单并取消，数据库与新卡数不变。
2. 正反拖选、跨行 / 句 / 段、译文混选、代码、旧选区外右键、超 600 字符；复制不截断、目标不串。
3. 短语新建、重复、已忽略 / 删除的同名条目、失败与撤销；不能误删已有词。接口 `undo` 返回需要对应 Core 验证。
4. 词卡 / 浮条 / 菜单互斥，朗读模式右键不跳读，显式连续播放才跳到目标；短句发音打断播放后的状态正确。
5. 无模型、离线词典、剪贴板 / TTS / 写入失败反馈；连接模型不自动补发。
6. mac 原生包次键、Control-click、取消、焦点与资源；其他平台键盘、子菜单和屏幕阅读器。
7. 浅 / 深 / 米色，960 / 1280 / 1440px、200% 缩放、右栏开关、视口四角与失焦；菜单无裁切、误点。

调研阶段只修改了文档和独立原型；用户随后确认实施，正式组件的改动与验证见 §8。原型检查不能替代真实 Core、模型、原生菜单与辅助技术验收。

**原型检查记录（2026-11-17）**：使用本机独立 Chromium 检查 320 / 393 / 960 / 1440px × 浅色 / 深色 / 米色 × 四类场景，共 48 组，菜单可见且位于视口内，页面无横向溢出或脚本异常。另走通真实次键、标词与撤销、句子子菜单与 Esc 焦点返回、目标句连续朗读示意、短语重复 / 撤销、选区“更多”、代码专用菜单、解释目标、Shift+F10 / End，以及跨句原文与含可见译文的混合选区。已查看桌面及窄屏截图；原型只演示结果落点，不验证真实词典、声音、模型与数据写回。脚本语法、文档本地链接和 `git diff --check` 通过。

## 8. 正式组件实施（2026-11-17）

- `reader/contextTarget.ts` 按正文范围、选区命中矩形、原 token 偏移解析目标；代码 / 译文混选只复制，跨句材料不伪造句子 id，短语只接受完整词边界。`SectionView` 的新增属性为可选，手机没有桌面菜单入口。
- `reader/ReaderMenu.tsx` 提供对象菜单、选区“更多”、短语只读查重、学习状态勾选与撤销；同一文章的模型问题进入已有 Tibi 对话。正文里不着色的 5 / 97 状态通过不带句子 id 的只读查询补齐，不借查词改变学习状态。
- 网页菜单通过 `components/ContextMenu.tsx` 复用 Radix；旧菜单的关闭回调不能清除新目标，滚动关闭按弹出时的实际位置比较，避免迟到的旧滚动事件关闭新菜单。
- 原生菜单支持分隔、勾选、一级子菜单和逻辑坐标。弹出命令返回后保留动作回调，在后续交互 / 组件卸载时释放资源，并限制全局只保留最后一个弹出菜单。macOS 弹出流程见 §6。
- `ReadAloud` 接收带章节和目标句的播放请求；`useAloud` 区分读完即停与从目标句继续。原朗读条实例保留倍速等设置；新请求不会因词状态刷新而重新播放，开发环境 StrictMode 的首次效果重放也可正常启动。系统语音不可用时显示错误并恢复 idle；取消 / 被其他发音打断不当成语音失败。
- 无模型时问题立即按文章暂存为内存草稿，连接页往返不丢失选中文字与上下文，用户手动发送后清除；不会因模型连接成功自动补发，也不将旧文章问题发进新文章。
- Core 的 `terms.addPhrase` 保留 `Term` 返回形状并增加可选 `undo`；已有条目（含已知 / 忽略）不改状态、不建卡。新建和删除后恢复可撤销；新词 `terms.mark` 的撤销一并撤回本次词条、语境和复习卡，避免只移出词本却继续着色。无数据库迁移、无新增依赖。

复制使用冻结的完整原始选区，保留首尾空白、代码缩进与换行；只有判断词 / 短语及空选区时才使用去空白后的文本。超过 600 字符的选区只复制，不截断后发送。短语查询失败可重新打开同一目标菜单并重试，查询未完成时仍能执行复制。
