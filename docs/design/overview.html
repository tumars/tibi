01概览与原则 00 §1、§4

读真实英文材料，边读边把生词变成已知词；AI 以"Tibi"一个角色出现，它会做的事叫技能。产品、吉祥物（藏狐）和助手同名。首发人群：读英文技术文档和博客的程序员。

本地优先无网络、无 API Key 时导入、阅读、着色、词典、复习、系统朗读全部可用；技能是增强层，离线时跳过并标"可稍后补做"。
确定性的交给代码，判断和生成交给模型分词、词形、查词、FSRS、统计是能力；总结、讲解、推荐、出题、批改、洞察、整理记忆是技能。
能力即工具界面按钮、技能、外部 AI 工具（经 MCP）调用的是同一套能力定义。
过程可见、可控技能每一步写入存储后才显示；可暂停、取消、重试；写数据按权限先问、可撤销；花费按技能统计并受预算约束。
AI 结果全部缓存同一内容不重复调用，换模型后可手动重新生成。
业务逻辑在 TypeScriptRust 只做壳，降低开源贡献门槛。
用户可见的只有一个 Tibi。内部的专职子对话、委派、任务图都收在"过程卡"和任务中心里；设置里才按技能逐项配置（决策 C1–C5、B1–B8）。

03进程架构 05 §3、00 §4

两个进程：Tauri 应用（WebView + 很薄的 Rust 壳）和 Tibi Core（Node sidecar）。数据库只有一个写入者：Tibi Core。

为什么要有 Tibi Core

  • 数据库只能有一个写入者；界面进程不能同时写。
  • MCP Server、关窗口后继续跑的后台任务都要常驻 Node。
  • 导入一篇文章和记录它的任务步骤可以在同一个事务里提交。

通信与打包

  • JSON-RPC 2.0：请求走 invoke，事件经 Rust 转成 Tauri 事件推给 WebView。
  • Core 打包为单文件（Node SEA 或 Bun），约 50–90 MB，由 Tauri externalBin 携带。
  • API Key 存系统钥匙串，Core 按需向 Rust 取，只留内存，不落库不落日志。

04能力与技能 05 §4–§5、02 §6、§8

交给代码（能力）

结果唯一、必须正确、要离线、要快：分句分词、词形还原、查 ECDICT、按已知词库着色、FSRS 排期、统计聚合、朗读。

交给模型（技能）

需要理解、取舍、生成或多步规划：语境释义、总结、挑短语与长难句、判断类型难度、推荐文章、出题、批改、写洞察、整理记忆。

熟练度 terms.status

0 生词1 见过2 眼熟3 认得4 熟悉5 掌握97 标为已知98 忽略99 待确认

界面只显示名称。"已知词"（词汇量）= 熟悉 / 掌握 + 标为已知 + 词汇量测试与预标注推断为已知的词；"掌握"不再标注、不进复习。97 是批量标记的结果：不建卡、不进复习，不等于掌握，批量不动待确认词。点开生词自动变成"见过"并建卡（R5）。

08接口 06 全文、05 §3、02 §6；与 TibiKernel 一起在 M0 定稿

WebView ↔ Tibi Core：JSON-RPC 2.0

完整参数与返回见 docs/design/06-interface.md；这里的内容由同一份定义生成（_src/build_interface.py），类型用 TypeScript 写法。

约定

  • JSON-RPC 2.0：WebView 经 Tauri invoke("core_call") 发请求，Rust 转发到 Core 的 stdio；事件经 Rust 转成 Tauri 事件 core_event。
  • 长任务一律返回 { task_id }，进度走 task.update，结果走 task.done。
  • 写操作返回 Undo，统一用 system.undo 撤销，同时写入 skill_audit。
  • 分页 cursor + limit → Page<T>；时间为毫秒时间戳；错误用标准 JSON-RPC 码 + error.data.code 业务码。
  • path 只接受 pick_file 或拖入后登记的路径；网址由 Core 校验，禁内网地址；深链 tibi://import?url=… 校验后弹确认卡，确认后才抓取。
  • terms.lookup 是写操作：带句子时把生词自动设为见过并建卡，不返回 Undo。
  • 失败路径：调用前预留预算；模型不可用时 ai_status = deferred（稍后补做）；写能力带幂等键。

09权限与安全 05 §8、02 §6

三档权限模式

每次都问 / 标词自动、其余询问（默认）/ 全部自动。beforeTool 统一执行；技能的 SKILL.md 只能收紧。

审批卡

"Tibi 想…" + 将执行的工具与影响 + 允许 / 拒绝 / 修改后允许 / 以后这类自动。所有写操作进审计，可撤销。

没有任意代码执行

不注册 bash、文件读写类工具；代码模式暂不启用，需要时用 QuickJS 沙箱且只能调能力。

抓取与注入

只抓用户给的网址或白名单来源，Core 校验并禁内网地址；抓到的内容视为数据，不当指令；读过不可信内容的任务，写入和外联都要审批。

密钥

存系统钥匙串，Core 按需向 Rust 取，只留内存；不写数据库、不写日志。

花费

调用前预留预算，月预算与单任务上限有默认值；技能都由用户触发，没有定时运行；按技能可见。

入口

path 只认 pick_file 或拖入登记的路径；MCP 默认只读白名单；深链只认 tibi://import，校验后确认才抓取。

界面

严格 CSP；净化 Markdown，禁远程图。

删除

文章、卡片软删；用户删除记忆、对话时硬删。见 01 §9。
