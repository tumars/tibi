# 腾讯云下载、更新与公告

2026-11-16：用户确认先迁分发与公告，GitHub 保留源码和 CI。本文描述本次实现和上线条件，代码改好不等于线上已经切换。

## 分发设计

官网 `https://tibi.ferecord.com/#download` 提供安装入口；安装包、更新信息和公告放在现有腾讯云 COS，通过自己的域名 `https://dl.ferecord.com` 读取。用户侧全部读取静态文件，不增加云端业务服务器或数据库。2026-11-17 增加仅在本机运行的网页管理台，供维护者管理存储、发布和公告。

| 文件 | 用途 | 缓存 |
| --- | --- | --- |
| `/v0.2.0/<原文件名>` | 每个正式版本的签名安装包、更新包和校验和 | 版本文件发布后不再改写 |
| `/latest/Tibi_aarch64.dmg` 等 | 官网与客户端手动下载的固定入口 | `no-cache` |
| `/latest/SHA256SUMS.txt` | 固定下载文件名对应的 SHA-256 | `no-cache` |
| `/latest.json` | Tauri 更新信息，包地址指向同域名的版本目录 | `no-cache` |
| `/notice.json` | 公告；版本、平台、已读判断仍在本机完成 | `no-cache` |

客户端更新源固定在 `tauri.conf.json`，本机和 CI 构建一致。公告只从 COS 读取，删除 GitHub raw 回退和对应桌面 http 权限；更新失败给本机安装包与官网下载页。腾讯云不可用时按现有错误处理返回，下次再查。

更新包继续用现有 Ed25519 密钥签名，公钥不变；下载后验签、安装前备份、停 Core、安装重启的流程不变。COS 只保存公开文件，不保存更新私钥。Apple 签名与公证仍是 Mac 正式发行的前提。移动端只迁公告，应用安装与更新继续走各自应用商店。

## 本机直接发布

需要 Node.js 22.18+（推荐 24）、AWS CLI（COS 的 S3 兼容接口）；发布公告还需要已经 `pnpm install --frozen-lockfile`。本机凭据放在本项目被忽略的 `.env.cos`，文件权限为 `600`；发布工具自动加载，已有环境变量优先，CI 继续使用 secrets 注入。不要将真实密钥发到聊天或提交 Git：

| 本机环境变量 | 现有 CI secret |
| --- | --- |
| `BUCKET`（含 APPID 的桶名） | `CN_S3_BUCKET` |
| `S3_ENDPOINT`（该地域 COS 的 HTTPS 端点） | `CN_S3_ENDPOINT` |
| `AWS_DEFAULT_REGION` | `CN_S3_REGION` |
| `AWS_ACCESS_KEY_ID` | `CN_S3_ACCESS_KEY_ID` |
| `AWS_SECRET_ACCESS_KEY` | `CN_S3_SECRET_ACCESS_KEY` |

`BASE_URL` 默认 `https://dl.ferecord.com`，正式发布保持此值。原 `CN_MIRROR_BASE_URL` 不再控制客户端构建。使用只可读写此分发桶的发布凭据；桶允许公开读取，写入仍须认证。

Tibi 使用独立的 `tibi-releases-1252518482` 桶（`ap-guangzhou`）与专用发布子账号 `tibi-releases-ci`；本机使用 2026-11-17 新建的第二把访问密钥，原 CI 密钥保留。该账号只允许此桶列表读取、对象读取、上传及分片上传；删除权限仅限 `uploads/*`。不授予画海桶或账号管理权限，当前策略见 `admin/cos-policy.json`。

公告：修改仓库根目录 `notice.json`，运行：

```sh
pnpm publish:cos notice
```

工具先运行 `apps/desktop/test/notice.test.ts` 校验公告完整字段，再上传并核对公开内容。无需先推送 GitHub；发布后仍应将最终公告纳入源码记录，避免后续 CI 用旧内容覆盖。

版本：在仓库外整理已经完成签名、公证及安装验证的发行目录，包含安装包、更新包和 Tauri 格式的 `latest.json`。清单的 `version` 必须和 tag 一致，`platforms` 只列已经验证的平台；每项包含真实更新包 URL 的文件名和对应签名。工具用本地同名文件上传，重写 URL 到 COS，保留签名，不负责构建或生成签名。

```sh
pnpm publish:cos release /绝对路径/发行目录 v0.2.0
```

发布顺序：校验版本、签名字段和包是否存在 → 上传版本文件与重新计算的校验和 → 更新固定下载名及其校验和 → 验证更新包和固定安装包公开可读 → 最后切换 `latest.json` → 逐字核对线上更新信息。上传或包的公开访问失败时不切换更新指针；已传成功的文件可能保留，需要修复后重试。固定下载别名逐个替换，发布期间不保证整组原子切换。

上传使用单并发、5 MB 分片和标准重试，只作用于本次命令，不修改全局 AWS 配置。这是针对此前跨境上传停滞的调整，仍需真实上传验证；有条件时优先在本机或腾讯云同地域机器执行。不可覆盖已发行版本目录中的文件；修包要发新版本。

## 本机网页管理台

在仓库根目录执行：

```sh
pnpm admin
# 自定义端口（默认 4311）：
ADMIN_PORT=4312 pnpm admin
```

打开 `http://127.0.0.1:4311`。服务只在本机监听，凭据不会发送到浏览器。停止服务用终端的 Ctrl+C；任务进行时请等待完成后再停止。

页面提供：

- **文件存储**：浏览目录与分页、复制或打开公开链接；上传和删除 `uploads/` 内的普通文件，不会通过此入口改写更新清单、公告和版本文件。单文件最大 2 GB，流式写入本机临时目录后上传 COS。
- **版本发布**：填写发行目录（默认建议来自 `~/Documents/releases/Tibi/`），先查看版本、平台、文件大小、SHA-256 和更新包验签结果，再确认发行。相同或更早版本、已存在的版本目录被拦住。正式安装包的签名、公证和安装验证仍须完成，管理台不替代构建与公证。
- **公告推送**：表单编辑中文/英文、按钮链接、平台、低版本提醒和截止日期，实时预览后保存草稿，再确认推送。草稿保存至仓库根目录 `notice.json`，推送时固定一份快照；可移除公告并发布空列表停止后续展示。保存草稿不会自动推送。
- **最近操作**：查看运行状态、结果与日志。任务和公告快照保存在 `.tibi/admin/`，已被 Git 忽略。关闭网页不会停止后台任务；服务重启后，未完成任务显示为中断。

这里的推送是已有的应用内公告，客户端每天检查，遵循自动检查开关、平台、版本、日期与已读规则，不是即时系统通知。一般公告同一 ID 只提醒一次，需要再次提醒时使用新 ID。发布公告后应把最终 `notice.json` 纳入源码记录，以免后续 CI 用旧草稿覆盖。

管理台复用现有发布脚本和客户端公告校验；发布版本前将挑选出的产物复制到临时目录重新验签、核对检查时的 SHA-256，排除其他目录和配置文件。版本上传失败可能保留未发布的部分文件，管理台不会覆盖这些目录；应先核对失败日志和云端状态，使用新版本号或在控制台确认清理未发布目录后重试。完整设计见[本机分发管理台](../design/14-distribution-admin.md)。

## 可选的 CI 入口

`mirror-cn.yml`（界面名称 Publish to Tencent COS）可将已正式发布的 GitHub Release 文件传到 COS；`notice-cn.yml` 可在公告推到 main 后发布。两者复用本机工具和现有 `CN_S3_*` secrets，缺少配置明确失败，不再以成功状态跳过。它们是发布便利入口；读者下载与已安装应用运行均不经过 GitHub。

本机直接发布后，若还使用 CI，须保持 GitHub 中的版本文件、公告与 COS 一致；禁止用旧文件覆盖新公告或已发行的版本。GitHub 正式 Release 仍不能被后续构建覆盖，保留现有发行检查。
